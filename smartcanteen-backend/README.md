# PEARL API first release

Node.js 20+ and a MongoDB replica set (including a single-node local replica set) or Atlas are required. Inventory, slot holds, payment settlement and expiry use multi-document transactions; standalone MongoDB is deliberately rejected at server startup. Run `npm install`, then `npm start`.

Required environment: `MONGO_URI`, `JWT_SECRET`, `JWT_REFRESH_SECRET`, `CLIENT_URL`. PayHere checkout additionally requires `PAYHERE_MERCHANT_ID`, `PAYHERE_MERCHANT_SECRET`, `PAYHERE_NOTIFY_URL` (public HTTPS callback), `PAYHERE_BASE_URL` and `PAYHERE_SANDBOX=true` for sandbox only. Use the live PayHere endpoint and `PAYHERE_SANDBOX=false` for production. `ENABLE_DEMO_PAYMENTS=true` explicitly enables the card-free demo confirmation endpoint in nonproduction; production always disables it. Do not collect card details in the client. Optional `RESERVATION_MINUTES` defaults to 10; use a positive integer. The default expiry worker runs every 30 seconds; also invoked before new orders and slot retrieval. Running multiple workers is safe.

Before deploying over existing data, back up the database, stop writes, and run `node scripts/migrate-first-release.js` with the target replica-set `MONGO_URI`. It cancels old unpaid orders, keeps legacy paid orders, issues pickup codes for their outstanding orders, initializes stock to zero, sets default weekday 08:00–18:00 hours, and rebuilds slot counts. Vendors must set stock before accepting new orders. Existing paid orders predate inventory tracking; their committed quantities are not deducted from newly configured stock. Run this migration once before resuming writes. It is idempotent for already migrated orders.

All endpoints use `/api` prefix and standard `{success,data}` responses. Student endpoints require student authentication; vendor pickup/profile/menu operations require an approved vendor.

- `GET /student/catalog?q=...`: `{vendors,items}`. Search is literal case-insensitive meal/vendor text. Public vendor fields exclude banking details. Vendor includes `isOpen, orderingReason, vendorProfile`; meal includes `effectiveAvailable,dailyStock,stockDate,stockRemaining`.
- `GET /student/favourites` and `PUT /student/favourites`: `{favourites:[mealId],vendorFavourites:[vendorId]}`. PUT accepts either array and preserves omitted fields; IDs are deduplicated, max 200 each.
- `POST /orders/:id/reorder`: `{vendorId,items:[{menuItemId,quantity,item}],unavailable:[{menuItemId,name,reason}]}`. Current prices and availability are returned for review; no order/payment is created.
- `POST /orders/intent`: `{vendorId,pickupSlotId,items:[{menuItemId,quantity}],specialInstructions?}` returns `orderId,totalAmount,pickupTime,items,expiresAt`. Reserves current-day stock and slot atomically; mixed vendors, past slots, paused/closed shops and insufficient stock fail. Quantities are merged per meal, at most 20 each.
- `GET /orders/:id/pickup-code`: `{code,orderId}` for the owning student and active paid order. Encode the exact random code as a QR payload.
- `POST /orders/pickup/verify`: `{code}`. Owning vendor only, paid ready orders only, single-use atomic completion, rate limited to 20 attempts per vendor per minute.
- `GET /payment/config`: `{demoEnabled}`. Demo confirmation remains `POST /orders/:id/confirm-payment` and uses the same reservation settlement checks.
- `POST /payment/initiate`: hosted PayHere form parameters. Payment return redirects are informational; only verified server notifications settle payment.
- `PATCH /vendor/profile`: existing fields plus `openingTime,closingTime,openDays,ordersPaused`. Hours use HH:MM, same-day closing after opening; Sunday=0. All schedule checks use Asia/Colombo. Orders are for the current business day only.
- `POST /menu`, `PUT /menu/:id`: accepts `dailyStock` nonnegative integer. DailyStock is the daily total, not an increment. Atomic updates preserve today's consumed/held quantities; remaining is `max(0,total-allocated)`. Inventory resets lazily at the Colombo date boundary.

PayHere notification signatures follow the official [Checkout API](https://support.payhere.lk/api-%26-mobile-sdk/checkout-api): uppercase MD5 of merchant ID + order ID + exact received amount + currency + status code + uppercase MD5 of merchant secret. Notifications validate configured merchant, LKR, order initiation and exact server-priced amount. Duplicate successful callbacks cannot reserve twice or emit duplicate order notifications. The durable vendor new-order notification is inserted in the same transaction as payment settlement. Notification insert failure rolls back settlement; provider retry can safely create both once. Realtime events are a best-effort supplement to that durable alert. Transient database failures return 500 so the provider can retry. Successful payments arriving after a hold expires are recorded with `paymentReviewRequired=true` and provider reference, remain cancelled, and never enter the vendor fulfilment queue. Operators must reconcile/refund these payments through PayHere; automatic refund integration is not included. A client must create a new intent after expiry.

`npm test` runs existing auth/middleware tests and replica-set inventory/payment/pickup integration tests using mongodb-memory-server. The first run downloads a MongoDB binary; restricted/offline environments should set `MONGOMS_SYSTEM_BINARY` to a local compatible mongod. Tests always use an ephemeral replica set and ignore application `MONGO_URI` to avoid deleting external data.
